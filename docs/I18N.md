# Languages

The site has two kinds of language, and they are independent.

- The interface locale: menus, buttons, status lines, tutorials, page titles. It is part of the URL: `/en/zip`, `/pt-br/zip`.
- The game language: the words of Termo and Wend, and what the chess coach says. It is a setting stored on the device.

A player can read the interface in English and play Termo in Portuguese, or the other way around. Changing one never changes the other.

## Interface locale

Locales are `en` (default) and `pt-br`. They are listed in `src/i18n/config.ts`, together with what each needs for `<html lang>`, `hreflang` and Open Graph.

Every page lives under `src/app/[locale]/`. The layout there builds the document, calls `setRequestLocale` and wraps the page in `NextIntlClientProvider`. `generateStaticParams` returns both locales, so every page is still prerendered as static HTML, once per locale.

The library is [next-intl](https://next-intl.dev). Its request config is `src/i18n/request.ts`, and `next.config.ts` loads it through the next-intl plugin.

### Getting to a locale

`src/proxy.ts` runs on every request, in two steps.

1. A shortcut domain (`zip.brunosilva.io`) is redirected to the canonical address with a 308. The target never has a locale, because that redirect is cached and the locale depends on the visitor.
2. A page path without a locale is redirected with a 307 to the visitor's locale. Files (`/sw.js`, `/manifest.webmanifest`, icons, images) have no locale and pass through.

The locale comes from `detectLocale` in `src/i18n/detect.ts`, in this order:

1. The `NEXT_LOCALE` cookie: the visitor already chose.
2. Vercel's `x-vercel-ip-country` header: a visitor in Brazil starts in Portuguese.
3. `Accept-Language`, best match first. Any Portuguese is `pt-br`, any English is `en`.
4. English.

A path that names a locale is served as it is, and the proxy stores that locale in the cookie. So the bare domain, the PWA start URL and every link shared before the site had languages all keep working: `/zip/play?seed=…` becomes `/pt-br/zip/play?seed=…`.

Share links are built without a locale on purpose. The person who opens one gets the puzzle in their own language.

### Switching

The flag in the header opens a menu with both locales (`src/shared/ui/locale-switcher.tsx`). The settings dialog has the same choice. Both call `useSwitchLocale`, which writes the cookie and replaces the URL with the same path and query string in the other locale. Progress is in IndexedDB, so a puzzle in progress is still there after the switch.

### Navigation

Use `Link`, `useRouter`, `usePathname` and `redirect` from `@/i18n/navigation` for every route of the site. They add the active locale: `href="/zip"` leads to `/pt-br/zip` on a Portuguese page. `GameMeta.path` in the registry has no locale.

## Messages

Messages are JSON files in `messages/<locale>/<namespace>.json`, in ICU syntax. The namespaces are listed in `src/i18n/messages.ts`:

| Namespace | Holds |
| --- | --- |
| `common` | What every game shares: header, controls, dialogs, result screen, practice setup, tutorial buttons |
| `games` | Name, tagline, description, mistake label and practice blurb of each game |
| `hub`, `settings`, `metadata` | The home screen, the settings dialog, page titles and descriptions |
| `zip`, `patches`, `chess`, `queens`, `sumbreak`, `wend`, `termo` | One per game, for its own text |

In a component: `const t = useTranslations("zip")`, then `t("status.solved")` or `t("status.endedEarly", { last: 9, count: 2 })`. Plurals are ICU plurals in the message, never string building in code.

`tests/shared/i18n.test.ts` checks that every locale has the same keys with the same placeholders, in every namespace.

### Text that comes from an engine

Engines are pure TypeScript with no React, and they do not hold sentences. A rule or a hint returns data: a code and the numbers its sentence needs. A `text.ts` module next to the engine turns that data into a sentence with a translator:

```ts
// src/games/zip/engine/rules.ts
return { code: "path-ended", values: { last: topology.lastNumber } };

// src/games/zip/engine/text.ts
export function moveErrorText(t: Translate, error: MoveError): string {
  return t(`error.${error.code}`, error.values);
}

// src/games/zip/hooks/use-zip-game.ts
const t = useTranslations("zip");
setStatus({ kind: "invalid", text: moveErrorText(t, error) });
```

`Translate` (`src/i18n/translate.ts`) is the shape of what `useTranslations(namespace)` returns. In a unit test or a command-line tool the same translator comes from `tests/i18n.ts`:

```ts
const t = translator("zip");           // English
const pt = translator("zip", "pt-br");
expect(moveErrorText(t, error)).toBe("Reach 2 before 3.");
```

## Game language

`Settings.gameLanguage` (`src/shared/storage/settings.ts`) is `"en"`, `"pt-br"` or `null`. `null` means the player never chose, and the games follow the interface locale. `useGameLanguage()` returns the language in effect.

The settings dialog offers it on the hub and in the games that depend on it. `GameMeta.language` says how a game depends on it:

- `"words"` (Termo, Wend): the puzzle is made of words, so each language has its own puzzles.
- `"voice"` (Chess): the puzzle is the same, and only the coach's lines change.

### Seeds

A puzzle made of words is a different puzzle in each language, so the language is part of the seed:

```
TERMO:lucky:1:hard          Portuguese
TERMO:lucky:1:hard:en       English
WEND:lucky:1:hard:7:en      English, 7 by 7
```

Portuguese is the language both games shipped in. It is the codec's `legacy` language and is left out of the seed, so every seed and link made before the games had two languages still opens the same words. `SeedCodec.languageOf(spec)` returns the language of a spec, and `resolve` takes a `lang` for loose seeds.

A shared link opens the words of its seed, whatever game language the receiver has. The setting decides the language of the daily puzzle and of new practice puzzles.

### Daily puzzles and streaks

A game made of words has one daily puzzle per language: same date, same number, same tier, different words. `getDailyInfo(codec, config, date, lang)` returns it, with `variant` set to the language code when it is not the legacy one.

Daily results are stored per variant (`termo:2026-11-25` and `termo@en:2026-11-25`), so finishing the day in one language does not close it in the other. The streak counts dates, not results: a date solved in any language counts once.

## Theme

`Settings.theme` is `"system"`, `"light"` or `"dark"`. `<html data-theme>` always holds the resolved value. An inline script in `<head>` (`src/shared/ui/theme-script.tsx`) sets it before the first paint, and `ThemeSync` keeps it current when the setting or the device's colour scheme changes. Stylesheets select on `:root[data-theme="dark"]` and have no `prefers-color-scheme` rule.

## Adding a locale

1. Add it to `LOCALES` and `LOCALE_META` in `src/i18n/config.ts`, and to `localeForLanguage` in `src/i18n/detect.ts`.
2. Copy `messages/en/` to `messages/<locale>/` and translate it.
3. Add a flag to `src/shared/ui/flags.tsx`.
4. Add it to `LOCALES` in `public/sw.js`.
5. For Termo and Wend, add a word list and a word bank for the language, or keep it out of the codecs' `languages.supported`.
